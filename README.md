# portfolio

A technical portfolio presenting five systems as case studies: the business problem, the
architecture decisions and what they cost, and the most interesting thing that went wrong in
each.

Built to be citable in a cold message. The audience is hiring managers and engineers in energy
access and distributed generation, so the site is in English.

---

## Running it

```bash
npm install
npm run dev        # http://localhost:3000
npm run build      # production build — every page is static
npm run lint
npm run assets     # regenerate the hero images from assets/source/
```

Node 20+. No environment variables, no database, no external services at runtime.

## Stack

| Piece | Choice | Why |
|---|---|---|
| Framework | Next.js 16, App Router | Everything prerenders to static HTML; Vercel is its native host |
| Content | MDX in-repo | One editor, no CMS to operate |
| Styling | Tailwind CSS v4 | Tokens live in `globals.css` under `@theme` |
| Diagrams | Hand-rolled SVG renderer | See `DECISIONS.md` — this replaced Mermaid |
| Analytics | Vercel Analytics | To find out whether cold outreach actually produces visits |

## Where the content lives

Editing a case study means touching two files, and they hold different layers:

```
src/content/projects.ts              layer 1 — the summary a hiring manager reads first
src/content/projects/<slug>.mdx      layer 2 — the technical deep dive
src/content/diagrams.ts              the architecture diagram for each slug
src/lib/site.ts                      bio, contact details, home-page headline figures
```

`projects.ts` is the index: adding an entry there, an MDX file with the matching slug, and a
diagram under the same key is all it takes to add a sixth case study. The route, the social
card, the footer link and the next-case-study navigation all follow from that list.

The deep-dive files use the same five `##` headings throughout. The page's table of contents is
generated by reading those headings out of the MDX at build time (`src/lib/toc.ts`), so renaming
a heading updates the navigation on its own.

## Confidentiality rules baked into the content

Four of the five projects belong to an employer, Mercaldas, and the rules below are not
editorial preference — they are the constraint the content was written under.

- **The company is named.** It is not anonymised.
- **Business figures appear as ranges, orders of magnitude or relative percentages.** Never
  exact revenue, margin, cost or volume figures.
- **Purely technical counts can be exact** where the project's own repository already states
  them: test counts, release numbers, product counts.
- **No source code and no screenshots of real operating data.** Architecture diagrams are fine.
- **Cortana carries none of this** — it is a personal project.

Every Mercaldas case study renders a visible note saying so. If you add a project, decide which
side of this line it falls on and set `confidential` accordingly.

## Interactive demos

Each case study carries a small interactive demo of the product. **Every one runs on synthetic
data and is labelled as a simulation in the interface.** They exist so a visitor can form an
impression by clicking rather than by reading, and they must never be mistakable for production
data. If you extend them, keep the label.

## Images

`assets/source/flow-field.png` is the artwork behind the GitHub profile header and the LinkedIn
banner, extracted from that repository's `header.svg` and committed here so this repo does not
depend on the other one. `npm run assets` derives the WebP hero plates and the favicon from it.
The site's palette is sampled from the same file, which is why the portfolio, the GitHub profile
and the CV read as one identity.

## Deploying

Pushes to `main` deploy through Vercel. Preview deployments come from pull requests.

## Structure

```
src/
  app/                  routes; opengraph-image.tsx files generate the social cards
  components/           Diagram, ProjectCard, site chrome, shared UI, demos/
  content/              projects.ts, diagrams.ts, projects/*.mdx
  lib/                  site config, table-of-contents reader, OG card
assets/source/          the original artwork, input to npm run assets
scripts/                asset pipeline and screenshot helpers
```

`DECISIONS.md` records where this implementation departed from the original plan, and why.
